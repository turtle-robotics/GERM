## Durable records and recovery

Migration 003 adds a canonical event envelope and foreign-key projection links to the existing event/sensor/actuator/maintenance tables, preserving older rows. It uses the M2 backup/checksum/transaction path; v2→v3 upgrade and recovery are tested. Legacy event IDs are preserved; new event-v1 records require canonical UUID IDs, explicit UTC, source/software version, experiment linkage, finite JSON object payload and known schema. Same ID/canonical content retry is a committed success; ID/content conflict is an explicit failure. Legacy rows lacking a canonical envelope cannot be silently claimed as identical retries.

Each system event and its actuator, sensor or maintenance projections commit in one SQLite transaction. Rejected commands remain diagnostic events and create no accepted actuator rows. Accepted commands record request/action/target/source, requested value, request/ACK times, ACK/transport failure, reported state and false physical-verification flag. Safe-state attempts record separate outcomes for symbolic pump/fan/lighting. Host logging rejects any claimed physical verification. Sensor faults retain raw diagnostics in event payloads and null decision values in projected readings; projection time is the UTC observation/event time, while the sample time remains in the reading payload. Maintenance entry/exit intent outcomes and startup/recovery checkpoints retain their own event IDs. A failed projection/COMMIT acknowledges nothing and retry cannot duplicate derived rows.

`HostPersistenceRuntime(gateway, repository)` explicitly registers symbolic dictionaries, attaches conservative M2 restart recovery and installs an `EventPipeline`. Existing sensor metadata must match the supplied normalized policies; conflicts fail rather than guessing units/location/periods. No safe state or healthy sample is seeded. No default app repository, physical adapter, production POST authorization or worker is enabled. `tick()` checkpoints changed durable intent and drains events. A host harness may explicitly run `run(stop_event, period_s)`; nothing starts on import. Trusted acquisition/profile integration must keep ticking to persist new state; dirty restart state remains inhibited meanwhile.

The drain takes an immutable queue snapshot under the state lock, releases it before any SQLite I/O and removes each envelope only after acknowledged COMMIT. Concurrent drains are serialized without blocking the command lock. Slow/failing/full/locked stores cannot prevent a safe-off adapter call or grant an energizing command. Errors, pending count, dropped count, poison count and last durable event ID/time are visible in `operating_state.logging`. Invalid/conflicting envelopes remain in the bounded queue and are marked poison while later valid events can commit. Queue overflow is permanently reported as loss/error, never durable success. No history pruning is implemented.

Command HTTP responses remain `logged=false`/pending while queued, with an event ID for correlation; they do not wait on logging or perform a duplicate legacy actuator write when the pipeline is installed. Existing M1 routes, confirmations, ACK and physical distinctions remain. The legacy optional logger is retained only when this explicit pipeline is absent. Final workflow outcomes are emitted after M2 checkpoint attempts, so persistence_failed is represented honestly.

Committed event IDs and canonical envelopes survive reopen, backup and restore. An event still in memory when a process/power failure occurs is **not durable** and can be lost. There is no claimed crash-proof pre-dispatch journal, guaranteed sensor/event cadence, complete scheduled operating record or zero-loss queue. Restart recovery always inhibits control and restores no prior controller/sensor health. Physical power-cut/endurance tests and a production supervision/flush policy remain separately gated. This limitation is tested explicitly rather than treating queued work as committed.
