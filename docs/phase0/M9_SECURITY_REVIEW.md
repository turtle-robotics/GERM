# M9 host security and command-boundary review

2026-11-16. This is a repository/host-test review, not a penetration test, authentication approval or permission to expose/deploy a service. The M1 gateway source and permission/state rules are unchanged. [Matrix](M9_ACCEPTANCE_MATRIX.md), [evidence](../evidence/m9/README.md).

| Surface | Observed boundary and evidence | Unresolved gate |
| --- | --- | --- |
| Actuator transitions | HMI routes → arduino_serial.send / grow.workflow → CommandGateway; schedule grants bind exact occurrence/command/generation. CommandGateway installs dispatch ContextVar before adapter.send/update. arduino_serial._exchange and upload_session require that context; physical get_serial refuses non-synthetic connections. Existing M1 tests plus M9 audited synthetic dispatch and endurance cover transitions, mode changes, maintenance, STOP, E-stop/restart reporting and rejected firmware. | Trusted Python can replace/inject adapters; this is not an untrusted-code sandbox or physical cutoff. No physical response deadline is established. |
| Pause revision race | HMI omits only optional expected revision for unconfirmed Pause, using the existing gateway contract. All commands still reach M1. Start/maintenance/other confirmed workflows retain nonce and exact revision. Explicit stale confirmed Start remains denied. | Historical timeout root cause is not proven exhaustively; documented demonstrated races have deterministic regressions. |
| POST authorization | Every registered POST route is tested with unset authorizer and forged body authority/simulation flags; all return 403 before mutation. GERM_SIMULATION, synthetic adapter, trusted authorizer and token are all required. Custom uploads remain denied. No browser/env/body switch enables production. | There is no approved production identity, roles, sessions, network perimeter or CSRF/Origin policy. Token is emitted in local HTML and is not identity authentication. Never expose the simulation harness. |
| HTTP reads/downloads | History, status, image, export and backup GET routes currently have no authentication. Download receipts/hashes and image/schema integrity are verified; no HTTP restore path accepts an arbitrary live destination. GETs do not activate control. | Anonymous local reads can disclose historical data and backup contents if the host is exposed. Authorization for read/download, TLS, roles, privacy, remote access and signed artifacts remain required decisions. |
| Exposure | app.py and offline_host.py bind 127.0.0.1, debug off; launcher has no bind-address option. Runtime assets/CSP are local. Tests bind random loopback ports only. | Loopback is not identity authentication. Host-header/DNS rebinding, malicious same-host software, forwarded ports, proxy configuration and OS permissions require production review. No network exposure was added. |
| Browser responses | Existing same-origin CSP, object/base/frame restrictions; API and now HTML no-store (HTML carries the local token); nosniff now applies to every response. Superseded state responses/errors cannot overwrite a newer poll. | Legacy unsafe-inline allowances remain. No claim of complete XSS defense, CSP audit or certified accessibility. Permission decisions remain server-side. |
| Configuration injection | Exact JSON shapes for jobs/recovery; fixed marked simulation workspace; synthetic gateway/camera/model ownership; no arbitrary command shell/model/path through HTTP. Existing request 1 MiB limit and filter/UUID bounds remain. | Factories, model manifests and Python authorizers are trusted process code; supply-chain, dependency patching, secret management, OS account isolation and secure installation need separate approval. |
| Paths and archives | M6/M7 reject traversal, absolute/reserved/case-colliding members, links, encryption and inconsistent manifests; validate hashes/JPEG dimensions/schema/ledger/FKs, enforce archive byte/member limits and restore only into new isolated exclusive destinations. SHA checks detect corruption, not authorship. | Same-user filesystem races/TOCTOU and hostile local writers are not eliminated by application checks. Backup authenticity/signatures, off-device copies and target filesystem/advisory-lock semantics remain open. |
| SQLite reads | Repository `_rows` now opens URI read-only/query-only connections; status queries avoid writer setup. A real concurrent WAL write and injected setup-lock probe verify the boundary. Writer synchronization and busy deadline remain unchanged. | Read failure is still explicit and can inhibit the host. No guarantee of availability under arbitrary filesystem/CPU contention or destructive local writers is claimed. |
| SQLite writers | Host repository instances share a weakly registered per-path writer lock. Coordination and SQLite busy wait share the configured budget; reads/backups stay read-only/concurrent and failed writes never claim a commit. M1 STOP dispatch does not depend on this lock. | This coordinates trusted in-process writers only; other processes, long native IO and target filesystem behavior still require verification. Over-budget contention remains a visible failure, never permission or cleanup. |
| Resource exhaustion | Existing bounded pages/filters/cursors, 1 MiB requests, one artifact worker per journal, row/member/byte/job/deadline quotas, bounded event/confirmation/request caches and explicit disk-full failures. M9 traces cap server records at 2048/client records at 512; endurance artifacts cap at 64 MiB/1000 files. No automatic cleanup. | No global HTTP rate/concurrency limit; a verified download may load up to the existing 256 MiB job limit into RAM per request. SQLite snapshot creation/integrity and native I/O cannot always be preempted by a deadline. No hostile-load/target-memory acceptance is claimed. |
| Durability | Queued logging is distinguished from failure/committed state. Explicit per-tick evidence permits continued core polling for concurrent pending events only when restart checkpoint is durable, repository ready and logging has no error; actuator scheduling is skipped for that tick. Unknown false results, poison/dropped events, DB/IO errors still degrade/revoke. Restart never resumes permissions or schedules. | A continuously busy producer can keep events queued; there is no new durable-success promise. Hardware/control production acceptance requires approved failure policy and measured target behavior. |

No historical files, images or receipts are deleted by hardening. Quota exhaustion fails rather than cleaning up. The conflicting retention proposal remains unapproved. Production POSTs and physical interfaces remain disabled; all earlier PRs remain unmerged. Security gaps above are blockers, not implicitly accepted risks.
