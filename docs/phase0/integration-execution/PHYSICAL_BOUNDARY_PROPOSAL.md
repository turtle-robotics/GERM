Define a trusted, immutable backend capability/session issued only by an approved startup factory, bound to gateway identity, exact release/configuration/protocol/device identity and approval scope. No HTTP/environment/body authority injection. Preserve the default unavailable adapter and every existing host test.
2. **Single serial owner.** New physical adapter/serial transport implementation owned only by M1; no UI/scheduler/profile/upload/mode helper may open/write the device directly. Resolve a verified stable USB identity only after G2 attachment approval; current `/dev/serial/by-id` is empty. Specify exclusive ownership, bounded open/read/write/partial-frame behavior and explicit disconnect states. Arduino open/DTR/RTS/reset/power effects require electrical review, not guessed defaults. Device attach itself remains a hardware operation.
3. **Protocol/ACK contract.** Audit installed firmware identity against the actual sketch/protocol before enabling dispatch. Existing accepted protocol-2 `CMD:<id>:...` and matched packet checks in `arduino_serial.py`/C++ harness are software candidates, not proof of flashed compatibility. Add recorded packet fixtures for malformed/late/duplicate/mismatched IDs, stale controller feedback, timeout, unplug/reconnect, reset and watchdog behavior. Accepted command, firmware ACK, durable outcome and independent physical verification remain separate. ACK alone must never set physically_verified=True. Upload stays denied until separately reviewed; no flashing is implemented now.
4. **Electrical mapping/configuration.** Version a reviewed as-built interface configuration and validate it before physical factory creation. Resolve red D3 versus candidate fan D3/red D5, D5 shared supply dimming/cooling/Peltier topology, white-channel installation/control, pump gate polarity and PWM/timer conflicts. 5. **Door and independent safety.** New read-only interlock adapter for approved reed-switch electrical interface, normalized door state, debounce/cadence/sequence/quality and missing/stale behavior. Feed `StateManager.observe` through reviewed ownership; never infer safe from a missing/open input. Confirm independent pump cutoff and measured door/E-stop/leak/thermal behavior before load commissioning. Maintenance, STOP, E-stop reporting, controlled reset and fresh confirmed Start retain M1 ownership; physical reset/sensor recovery cannot resume schedules.

Existing legacy GPIO4 helper is active and must not be stopped/shared/reassigned without that specific approval. Never alias electronics temperature to canopy/water temperature or invent healthy values. M4 workflows/schedules remain gateway clients. Preserve queued versus committed states and reject unsafe/restart/faulted automatic actions.
